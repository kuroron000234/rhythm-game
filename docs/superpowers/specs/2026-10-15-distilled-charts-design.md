# ブラウザ内 AI 譜面(MuG 蒸留)設計仕様

日付: 2026-10-15 / 前提: MuG 譜面は好評。ブラウザだけで完結させて GitHub Pages で公開したい

## 目的と成功基準
- MuG Diffusion(1.8GB, GPU)を先生にして、ブラウザで動く小さなモデル(数 MB)に譜面生成を真似させる
- 成功基準: (1) 確認用の曲で MuG 譜面とのノーツ一致 F1(±50ms、レーン無視)≥ 0.6 (2) GPU なしのブラウザで 4 分曲の生成が 10 秒以内 (3) ユーザーが遊び比べて「MuG と遜色ない」と判断

## データ
- 曲: ボカロと J-POP/アニソン半々。yt-dlp 検索(アーティスト名+MV)、2〜7 分、重複・年齢制限・ライブ/カバー/メドレーを除外。音源は手元(`~/rg-data/`)のみに置き、公開しない
- 試作 60 曲(学習 44 / 確認 8 / テスト 8)→ 見込みがあれば約 300 曲
- 手本: このPC(RTX 4060)の MuG で各曲 EASY/NORMAL/HARD を生成(星 1.3 / 2.2 / 3.2、拍スナップなし)

## 特徴量(Python と TypeScript で完全一致させる)
- 22050Hz モノラル、STFT n_fft 1024 / hop 256(11.6ms)/ periodic Hann / 中心化(両端ゼロ埋め)
- パワースペクトル → 64 バンドのメル(30Hz〜11025Hz、HTK 式メル尺度、三角フィルタ、面積正規化なし)→ log(mel + 1e-6)→ 曲ごとに平均 0・分散 1 に正規化
- 一致テスト: 同じ PCM から両方で計算し、最大誤差 1e-3 以下

## モデル
- 入力: メル 64 × T フレーム + 難易度(0/1/2)
- 1D 畳み込み前段 → 難易度埋め込みを加算 → 膨張畳み込み残差ブロック(128ch、膨張 1〜32 を 2 周)→ 双方向 GRU(各方向 96)→ 出力 8ch(4 レーン × {ノーツ開始, ロング継続})
- 損失: BCE。開始は前後 1 フレームに 0.3 のぼかし、正例の重み 10
- ONNX(opset 17)に書き出し、onnxruntime-web(WASM)で実行

## デコード(ブラウザ)
- レーンごとに開始確率の極大(±3 フレーム)が閾値以上の所をノーツに。閾値は難易度ごとに確認用の曲で MuG のノーツ数に合うよう決めて、モデルと一緒に保存
- 開始直後からロング継続確率 0.5 以上が 0.15 秒以上続けばロング、下回った所で終わり
- その後は既存の `chartFromOsu`(拍グリッドへの吸着、同レーン間隔、クリティカル)に通す

## 組み込みと公開
- 曲を読み込むと、Worker で従来解析(拍・パルス)とモデル推論を行い、「AI 譜面(ブラウザ)」として表示。モデルが読めない/失敗時は従来譜面
- ローカルサーバーが無くても動く。URL 読み込みはサーバーがある時だけ表示(GitHub Pages ではファイルのドロップのみ)
- GitHub Actions で `main` から Pages に公開(リポジトリの公開設定はユーザーが決める)
- 学習スクリプトは `ml/` に置く(音源・手本・重みはコミットしない。公開するのは ONNX モデルのみ)
