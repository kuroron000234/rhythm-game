# AI 譜面(ボーカル連動)設計仕様

日付: 2026-10-13
前提: `2026-10-13-rhythm-game-design.md` の実装済みゲーム

## 1. 目的と成功基準

ユーザーの不満: (1) 叩く音がボーカル・メロディと合わない (2) 曲の盛り上がりが譜面に出ない (3) ロングノーツが伸ばす音と合わない。

- AI 音源分離(Demucs)でボーカルを取り出し、ボーカルの音符に沿ってノーツとロングを置く
- 区間ごとの盛り上がりで密度を 0.3〜1.3 倍に動かし、同時押し・クリティカルをサビに寄せる
- 低スペック対応: GPU があれば使い、なければ CPU、Demucs が無ければ従来解析のみ。AI 処理中でも従来譜面ですぐ遊べる
- 成功基準: 実曲 3 曲で、AI 譜面の HARD においてボーカル音符の 70% 以上にノーツが ±40ms で対応し、1 拍以上伸ばすボーカル音の 50% 以上がロングになる。サビ区間の密度がヴァース区間の 1.5 倍以上

スコープ外: 音程によるレーン配置、ボーカル以外(ギター等)の個別パート分離、AI 譜面と通常譜面の手動切り替え UI。

## 2. 測定済みの前提(spike)

- htdemucs `--two-stems vocals`: RTX 4060 で 16–19 秒、i7-13620H CPU で 111 秒(4 分曲)
- 分離ボーカルへの YIN ピッチ追跡 + 音符分割で、歌の音程と区切りをおおむね追える(1 曲 1–2 秒)

## 3. 構成

### サーバー
- `server/separator.ts`: Demucs 実行。Python は `RG_PYTHON` → `<project>/.venv-ai/bin/python` の順で探す。起動時に `import demucs, torch` と `torch.cuda.is_available()` を確認し `{ device: 'cuda' | 'cpu' } | null` を返す
- 実行: `python -m demucs -n htdemucs --two-stems vocals -d <device> -o <tmp> -- <audio>` → ffmpeg でモノラル 22050Hz FLAC に変換(タイミング誤差のない可逆形式)→ `<cache>/<id>/stems/{vocals,accomp}.flac`
- ジョブキュー: 同時 1 件、同じ id は重複させない。状態 `queued | running | done | error`、進捗は Demucs の tqdm 出力の % を拾う
- API
  - `GET /api/status` → `{ ytdlp, ai: { device } | null }`
  - `POST /api/upload/:id`(生バイト, 上限 300MB, ヘッダ `x-filename`)→ ドロップしたファイルをキャッシュに登録
  - `POST /api/stems/:id` → キュー投入(音声が無ければ 404、AI 無しなら 503)
  - `GET /api/stems/:id` → `{ state, progress?, error? }`(未投入なら `{ state: 'none' }`)
  - `GET /api/stems/:id/:stem`(`vocals` | `accomp`)→ FLAC
- `npm run setup-ai`: `.venv-ai` を `--system-site-packages` で作り demucs を入れる。torch が import できなければ CPU 版 torch を入れる

### ブラウザ
- 読み込み後は従来どおり通常譜面を作ってすぐ選曲画面へ
- AI が使えて AI 譜面が未生成なら、(ファイルならアップロードしてから)分離を依頼し、2 秒ごとに状態を確認。完了したら stems を取得・デコードし Worker で AI 解析 → IndexedDB に `ai:` 付きで保存
- 選曲画面: 状態表示(「AI 解析待ち」「AI 分離中 42%」「AI 譜面」「AI 解析失敗」)。AI 譜面ができたらその場で差し替え、以後の読み込みでは AI 譜面を優先
- プレイ中は分離の確認を止めない(裏で進む)

## 4. 解析

### 4.1 区間の盛り上がり(通常・AI 共通)
- 拍グリッドから 4 小節(16 拍)ごとの区間を作り、各区間で: 音量(RMS 平均)、オンセット密度、繰り返し度(小節ごとのクロマ 12 次元ベクトルを他の区間と比べた最大コサイン類似度)
- 強さ = 0.55×音量 + 0.25×密度 + 0.20×繰り返し度×音量(各値は曲内パーセンタイル順位で 0..1 に正規化)
- 密度係数 = 0.3 + 1.0 × 強さ(曲内で必ず起伏が出る)
- 同時押しの割合は強さ 0.7 以上の区間で 1.5 倍、0.3 未満では 0。クリティカルは強さ 0.6 以上の区間からのみ
- AI モードでは音量・密度を伴奏ステムから計算

### 4.2 ボーカル音符抽出(`src/analysis/vocal.ts`)
- 22050Hz、窓 1024 / ホップ 256。YIN(FFT 自己相関 + 正確な差分関数)、閾値 0.3、信頼度 0.6 以上かつ音量が上位 5% 値の 6% 以上で有声
- 5 フレームの中央値で平滑化、0.8 半音以上のずれが 3 フレーム続いたら次の音符。70ms 未満の隙間で音程差 0.9 半音未満(オクターブ誤り含む)は結合。4 フレーム未満の音符は捨てる
- 出力: `{ t, dur, midi, level }[]`

### 4.3 AI 譜面生成
- 拍グリッドとオンセットは伴奏ステムから
- 候補: ボーカル音符(スコア 0.65 + 0.35×level、スナップ許容は 16 分の 0.5)+ 伴奏オンセット(従来スコア × 0.7)。同じスロットならボーカル優先
- ロング(NORMAL 以上): 1 拍以上のボーカル音符。長さは半拍単位に切り捨て、最大 4 拍、全体の 15% まで
- 密度上限・レーン規則・クリティカル・決定性は従来どおり

## 5. エラー処理
- Demucs 失敗: 状態 `error` とメッセージ(末尾 1 行)。選曲画面に「AI 解析失敗」と表示し通常譜面のまま
- サーバー停止中・AI 無し: 何も表示せず通常譜面のみ
- 途中で別の曲を開いた: キューは裏で続く。次に開いたとき完了していれば AI 譜面

## 6. テスト
- vocal.ts: 倍音付き合成「歌」(既知の音程・長さ・隙間、ビブラート付きの長音)で音符数・開始 ±30ms・長さ ±15%・音程 ±0.5 半音、ビブラートの長音が 1 音符のまま
- 盛り上がり: 静かなヴァース + 大きく繰り返すサビの合成曲でサビの密度がヴァースの 1.5 倍以上
- AI 譜面: 合成ボーカル + ドラム伴奏で、HARD のボーカル音符対応率 ≥ 70%、長音のロング化 ≥ 50%、ロング中の同手禁止などの既存規則
- サーバー: 偽 separator でキュー状態遷移・重複排除・アップロード・stems 配信・AI 無しで 503
- 実機: GPU で実曲 3 曲、成功基準の数値を計測
