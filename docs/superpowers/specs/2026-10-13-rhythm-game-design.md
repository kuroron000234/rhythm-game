# 自動譜面生成リズムゲーム 設計仕様

日付: 2026-10-13
ステータス: レビュー待ち

## 1. 目的と成功基準

YouTube 等のリンクを貼る(またはローカル音声ファイルをドロップする)と、その曲から数秒〜十数秒で譜面を自動生成し、すぐに遊べる 4 レーン音ゲー。

- 見た目・手触りのイメージ: プロジェクトセカイの 4 レーン版 + Sparebeat(奥行きのあるレーン、暗背景のクリーンなネオン系)
- 利用形態: 自分の PC 上でローカルサーバーを起動し、ブラウザ(localhost)で遊ぶ個人用。公開ホスティングはしない
- 成功基準: 自分の好きな曲で「曲に合っている」と感じる譜面が出て、毎日遊べる完成度(3 難易度、判定、スコア/コンボ、ロングノーツ、ハイスコア保存、オフセット調整、演出)

### スコープ外
- フリックノーツ、タッチ/スマホ操作
- リアルタイム(先読みなし)解析、PC で再生中の音のキャプチャ
- 公開サーバー運用、オンラインランキング
- 譜面エディタ

## 2. 全体構成

```
rhythm-game/
  server/                Node 22 + Express (TypeScript, tsx で実行)
    index.ts             静的配信 + API
    fetchAudio.ts        yt-dlp 呼び出し(音声のみ, 変換なし: m4a/opus)
    cache.ts             ~/.cache/rhythm-game/<id>/ に audio + meta.json
  src/                   ブラウザ側 (Vite + TypeScript)
    analysis/            Web Worker 内で実行。DOM 非依存の純関数のみ
      spectrum.ts        ダウンサンプル, STFT, 帯域エネルギー
      onsets.ts          帯域別オンセット検出
      tempo.ts           BPM 推定 + ビートトラッキング
      chart.ts           難易度別譜面生成
      params.ts          生成パラメータを一元管理
      worker.ts          Worker エントリ
    game/
      clock.ts           AudioContext.currentTime 基準の曲内時刻
      input.ts           キー入力 → 曲内時刻への変換
      judge.ts           判定・スコア・コンボ・ライフ
      renderer.ts        Canvas2D 透視描画・エフェクト
    ui/                  タイトル / 解析中 / 難易度選択 / プレイ / リザルト / 設定
    storage.ts           IndexedDB(譜面キャッシュ, ハイスコア, 設定)
  test/                  Vitest
```

npm スクリプト: `npm start` で Vite ビルド済みフロント + API を 1 プロセスで配信(開発時は `npm run dev` で Vite dev server + API プロキシ)。

## 3. データフロー

1. URL 入力 → `POST /api/fetch {url}`
2. サーバー: URL から動画 ID を抽出(`yt-dlp --print id`)→ キャッシュにあれば即返却。なければ `yt-dlp -f bestaudio --no-playlist` で取得し、タイトル・長さ・サムネイル URL を meta.json に保存
3. レスポンス: `{id, title, duration, thumbnail}`。音声は `GET /api/audio/:id` で取得
4. ブラウザ: `decodeAudioData` → PCM を Worker へ転送(Transferable)→ 3 難易度分の譜面を生成 → IndexedDB に保存(キー: 曲 ID + 譜面フォーマットバージョン)
5. ファイルドロップの場合: 曲 ID = ファイル内容の SHA-256 先頭 16 桁。手順 4 から同じ

## 4. 譜面生成アルゴリズム

### 4.1 前処理
- モノラル化、22050Hz にリサンプル(OfflineAudioContext)
- STFT: 窓 2048 (Hann), ホップ 512 (≈23.2ms)
- 帯域: 低 <150Hz / 中 150–2000Hz / 高 >2000Hz の対数圧縮エネルギー

### 4.2 オンセット検出
- 帯域ごとにスペクトルフラックス(正の差分のみの総和)
- 適応しきい値 = 移動中央値(±0.5 秒) × k + δ、ローカル最大のみ採用、最小間隔 50ms
- 出力: `{t, strength, band}[]`。全帯域合算フラックスも保持

### 4.3 テンポ・拍
- 合算フラックスの自己相関で 70–200 BPM の候補を求め、90–180 に寄せて倍/半テンを解消
- Ellis の動的計画法ビートトラッキングで拍位置列を得る(テンポ揺れ追従)
- 拍間を 4 分割した 16 分スロットのグリッドを構成
- 拍の安定度(拍間隔の変動係数)が閾値超なら「グリッド非信頼」とし、スナップを弱めてオンセット時刻ベースで配置、UI に表示

### 4.4 ノーツ配置(難易度別)

| | スロット | 最大密度 | 同時押し |
|---|---|---|---|
| EASY | 4 分 | 約 3 notes/s | なし |
| NORMAL | 8 分 | 約 6 notes/s | 強拍のみ 2 個 |
| HARD | 16 分 | 約 10 notes/s | あり |

- オンセットを最近傍スロットにスナップ(許容幅外は破棄)
- スロットスコア = オンセット強度 + 拍頭ボーナス
- 区間 RMS(約 4 小節単位)から盛り上がり係数を出し、密度上限をサビで増、静部で減
- スコア上位から密度上限まで採用

### 4.5 レーン割り当て
- 帯域ベース: 低音 → 外側(D/K)寄り、高音 → 内側(F/J)寄り、中音は前後の流れで決定
- 制約(重み付きペナルティで評価): 8 分より細かい同レーン連打禁止、同一パターン 3 回以上の反復を崩す、左右の手の偏り抑制
- 乱数は曲 ID 由来のシード固定 → 同じ曲は常に同じ譜面

### 4.6 特殊ノーツ
- ロングノーツ(NORMAL 以上): 中帯域エネルギーがオンセット後 2 拍以上ほぼ減衰せず持続する区間。保持中は同じ手側のレーンに新規ノーツを置かない
- クリティカルノーツ(金色): 曲中で特に強いアクセント(合算フラックスの上位、かつ拍頭)に限定。判定幅は通常と同じで得点の重みが 2 倍

### 4.7 出力形式
```ts
interface Chart {
  version: number;        // フォーマット/生成ロジックのバージョン。変わったら再生成
  bpm: number;
  gridReliable: boolean;
  difficulty: 'easy' | 'normal' | 'hard';
  notes: { t: number; lane: 0 | 1 | 2 | 3; dur?: number; critical?: boolean }[];
}
```

## 5. ゲーム部分

### 5.1 時刻管理
- 曲内時刻は常に `AudioContext.currentTime` から算出(rAF 時刻は使わない)。`outputLatency` を考慮
- 入力時刻は `KeyboardEvent.timeStamp` を `performance.now()` と `AudioContext.getOutputTimestamp()` の対応で曲内時刻に変換
- 判定オフセット(音)と表示オフセット(見た目)を別々に適用

### 5.2 判定・スコア
| 判定 | 幅 | 得点率 | コンボ |
|---|---|---|---|
| PERFECT | ±40ms | 100% | 継続 |
| GREAT | ±80ms | 70% | 継続 |
| GOOD | ±120ms | 40% | 継続 |
| MISS | 範囲外 / 見逃し | 0% | 切断 |

- スコア: 1,000,000 点満点(クリティカルは重み 2 で正規化)
- ランク: S ≥ 950k, A ≥ 900k, B ≥ 800k, C < 800k
- FULL COMBO / ALL PERFECT 表示
- ロングノーツ: 始点で判定、終点 ±120ms 以内のリリースで成立、途中リリースは MISS
- ライフ: 初期 100。MISS −8、GOOD ±0、GREAT +0.5、PERFECT +1(上限 100)。0 になっても曲は継続し、リザルトで CLEAR / FAILED

### 5.3 描画・演出(Canvas2D)
- 透視投影: 奥が狭い台形の 4 レーン、ノーツは奥から手前へ。奥行き z → 画面 y とスケールを射影変換
- ハイスピ設定(初期値はやや速め)
- 判定ラインのヒットエフェクト(光の粒子)、レーンの発光、判定文字とコンボのポップ表示
- 暗背景のネオン系配色。背景は低帯域エネルギーに同期した控えめな脈動。YouTube の曲はサムネイルをぼかして背景に使う
- ヒット音は生成した短いクリック音(ON/OFF 可)

### 5.4 画面フロー
タイトル(URL 入力 / ファイルドロップ / 履歴とハイスコア)→ 取得・解析の進捗 → 難易度選択(ノーツ数、BPM 表示)→ プレイ(Esc: 一時停止 / リトライ / 終了)→ リザルト(スコア、ランク、判定内訳、最大コンボ、CLEAR/FAILED、自己ベスト更新表示)

### 5.5 設定
- 判定オフセットの自動調整(一定リズムを叩いて平均ズレを測定)+ 手動調整
- 表示オフセット、ハイスピ、キー配置(既定 D F J K)、曲の音量、ヒット音の ON/OFF
- IndexedDB に保存

## 6. エラー処理
- yt-dlp 失敗: stderr の要点を表示し「`yt-dlp -U` で更新」を案内
- プレイリスト URL は `--no-playlist` で単曲扱い。20 分超の動画は拒否
- yt-dlp 未インストール: 起動時にチェックして警告(ファイルドロップは引き続き使える)
- デコード失敗: 非対応形式と表示
- グリッド非信頼: 4.3 のフォールバックに切り替えて UI に表示
- IndexedDB 使用不可: キャッシュとハイスコアなしで動作継続

## 7. テスト
- `analysis/`(Vitest, Node 上で実行): 合成音源(既知 BPM のクリック、キック/スネア/ハイハットのパターン)で
  - BPM 誤差 ±1 以内
  - オンセット再現率 ≥ 90%(±30ms)
  - 譜面が密度上限・同レーン連打禁止・ロング中の同手禁止を満たす
  - 同一入力 → 同一譜面(決定性)
- `judge.ts`: 判定境界、コンボ、ロングノーツ、ライフ、スコア正規化
- サーバー: yt-dlp をモックして、キャッシュヒット、エラー伝搬、長さ制限
- 手動: 実際の曲を数曲取得し、各難易度をプレイして体感確認
